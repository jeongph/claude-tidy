# Tidy — 세션 마무리 정리

세션을 닫기 전에 **흘린 것이 없는지** 검사하는 규율이다. 컨텍스트가 사라지면 "빠뜨렸다는 사실" 자체를 잊는다 — 그 전에 잡는다.

핵심 원칙:
- **검사가 먼저, 처리는 확인 후.** 발견한 문제를 임의로 수정하지 않는다. 보고하고, 사용자가 승인한 항목만 처리한다.
- **해당되는 검사만 수행한다.** 각 체크는 감지 조건을 갖는다. 프로젝트에 해당 없는 체크는 조용히 건너뛴다 (보고서에 "해당 없음"을 늘어놓지 않는다).
- **Git 상태와 대화를 함께 확인한다.** 이번 세션에서 하기로 한 작업과 실제로 수행한 작업을 비교한다.

---

## 절차

### 1. 체크 로드 및 감지

`checks/` 디렉토리의 모든 `.md` 파일을 읽는다. 각 파일의 **감지 조건** 섹션을 현재 프로젝트·세션에 대해 평가해 수행할 체크 목록을 확정한다.

### 2. 체크 실행

해당되는 체크를 각 파일의 **검사 절차**대로 수행한다. 서로 독립적이므로 병렬 수행해도 된다 (대형 세션이면 Task로 위임 가능하되, 대화 컨텍스트가 필요한 체크는 직접 수행한다).

### 3. 결과 보고

체크리스트 형태로 보고한다:

```
## 세션 정리 결과

- ✅ 커밋/푸시 — 누락 없음
- ⚠️ 히스토리 — 이번 세션의 ○○ 작업이 기록되지 않음
- ⚠️ 잊힌 작업 — 세션 초반에 언급한 "△△ 리팩토링"이 수행되지 않음
- ✅ 워크트리 — 워크트리 아님 (해당 없음 항목은 이유가 유의미할 때만 표기)

### 처리 제안
1. ...
```

### 4. 처리

⚠️ 항목마다 처리 방법을 제안하고, 사용자가 승인한 것만 실행한다. 커밋·이슈 코멘트·외부 기록처럼 **밖으로 나가는 작업은 반드시 내용을 먼저 보여주고** 확인받는다.

## 새 체크 추가하기

`checks/<이름>.md` 파일 하나를 추가하면 끝이다. 포맷:

```markdown
---
name: <kebab-case 이름>
description: <한 줄 요약>
---

## 감지 조건
<이 체크가 이 프로젝트/세션에 해당되는지 판단하는 기준>

## 검사 절차
<수행할 검사 단계>

## 처리
<문제 발견 시 제안할 처리 방법>
```
