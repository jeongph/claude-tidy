# Handoff — 세션 인수인계

세션의 *작업 중인 머릿속 상태*를 저장하는 규율이다. 목적은 하나 — **다음 세션(또는 다른 사람)이 컨텍스트 없이도 즉시 이어받게 한다**.

tidy가 "흘린 것 회수"라면, handoff는 tidy에 더해 "상태 기록과 인계"까지 한다.

---

## 절차

### 단계 0: 핸드오프 필요 판단

이어받을 상태가 있는가 — 진행 중 작업·미커밋 변경·연 PR·미완 다음 스텝 중 하나라도 있으면 진행. 없으면(단순 질의·완결된 사소한 수정) "핸드오프할 상태가 없습니다"라고 알리고 종료한다.

### 단계 1: 세션 정리 (tidy 재사용)

`tidy` 스킬의 절차를 그대로 수행한다 — `${CLAUDE_PLUGIN_ROOT}/skills/tidy/checks/`의 체크들을 감지·실행·보고·처리. 핸드오프 전에 흘린 것부터 회수해야 기록할 상태가 정확해진다.

특히 `forgotten-tasks` 체크에서 나온 미처리 항목은 삭제하지 말고 단계 3의 "남은 작업"으로 넘긴다.

### 단계 2: 세션 상태 수집

git과 대화에서 인계 재료를 모은다.

```bash
git branch --show-current
git status --short
git log --oneline -8
```

- **완료한 작업 단위** / **진행 중 작업과 도달 지점** / **다음 단일 액션**
- **블로커·열린 루프** — 기다리는 것(CI·리뷰·외부 의존)과 확인 위치
- **이번 세션의 결정과 근거** — 다음 세션이 재논의하지 않게
- **발견한 함정** — future-you 시간 절약
- **부작용** — 만든 브랜치/PR/태그/배포/외부 전송 (고아 리소스 방지)
- **검증 상태** — build/test/deploy 실제 결과. "됐다"고 얼버무리지 않는다

### 단계 3: 상황 기록

프로젝트가 쓰는 기록 체계를 감지해 그에 맞게 기록한다. 여러 개면 각각 (역할이 다르다):

| 감지 | 기록 |
|---|---|
| `docs/knowledge/` (OKF) | `references/okf-handoff.md` 절차 수행 — History 노드 마감 + resume 스냅샷(`session-state.md`) + 트래커 동기화 |
| `docs/tasks.md` (작업 상태판) | 진행중 항목의 상태·도달 지점 갱신, 완료 항목 제거 |
| 이슈 트래커 (GitHub 등) | 진행 중 이슈에 상태 코멘트 (draft 확인 후) |
| `.remember/` (개인 메모리) | 버퍼에 기록 또는 resume 위치 포인터 한 줄 |
| 아무것도 없음 | 기록 파일을 강요하지 않는다 — 단계 4의 인계 노트 출력만으로 마감 |

기록 원칙 (무엇을 담나 / 안 담나):

- **담는다**: 다음 액션 한 줄, 진행 상태, 블로커, 결정+근거, 함정, 부작용, 검증 상태
- **안 담는다**: 대화 전체 복붙, 코드 복제(파일 경로·SHA로 가리킨다), 완료 작업의 장문 서술
- **커밋되는 기록에는 개인·비공개 정보를 넣지 않는다** — 자격증명, 개인정보, 한 세션에만 의미 있는 것

### 단계 4: 인계 노트 출력

사용자에게 다음 세션에 그대로 쓸 수 있는 요약을 출력한다:

```
## 핸드오프 완료

### ▶ 여기서 시작
<다음 단일 액션 한 줄>

### 이번 세션 완료
- ...

### 진행 중 / 남은 작업
- ...

### 블로커
- ...

### 복원 경로
- <기록 위치 (session-state.md, tasks.md 등)> — 새 세션에서 이 파일부터 읽으면 됨
```

끝으로 재개 방법을 안내한다: 새 세션에서 복원 경로의 파일을 읽거나, compact라면 그대로 진행해도 기록이 살아 있음을 알린다.

---

## 자기 점검 (마감 전)

- 다음 세션이 **"여기서 시작" 한 줄로 즉시 재개**할 수 있는가
- 만든 브랜치/PR/태그/배포가 부작용 목록에 다 있는가 (고아 없음)
- 검증 상태가 사실대로 적혔는가
- 커밋되는 기록에 개인·비밀 정보가 없는가

## 언제 스킵하나

넘길 상태가 없는 세션은 ceremony를 생략한다. 핸드오프는 *이어받을 게 있을 때*의 도구다.
